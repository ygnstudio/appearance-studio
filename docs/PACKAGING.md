# 打包说明

[返回首页](../README.md)

运行 `npm run package`，先构建并运行全部逻辑测试，再在 `dist/release-<随机标识>/snippet-editor/` 生成独立安装目录。每次使用新目录，避免旧数据混入。目录仅包含：

- `main.js`
- `manifest.json`
- `styles.css`

打包使用明确文件名单，拒绝符号链接、版本不一致及常见凭据/个人路径模式，并核对输出内容。它不会复制 `data.json`、草稿、历史、迁移备份、测试截图或笔记，也不会上传或发布。升级时只替换上述三个文件，保留用户原来的 `data.json`。

自动扫描不能识别所有秘密；正式发布仍需人工检查文件内容、截图、文档与 Git 历史。作者署名与许可证版权信息有意保留。

## 发布前

- 检查 `manifest.json`、`package.json` 和更新记录的版本一致。
- 运行 `npm run package`，从输出的新目录取文件，不从已安装插件目录取文件。
- 用空白测试库安装，检查默认设置、CSS 开关、导入导出和卸载清理；平台测试如未完成应明确说明。
- 核查源码、文档、Git 提交身份及所有将上传的文件。不要把真实库截图、草稿、备份和运行数据放入仓库。

仓库推送不会自动创建 GitHub Release。需要发布安装包时，使用与已验证提交一致的版本标签，附件仅包含上述三个文件，并确认上传文件与本地打包结果一致。
